## 功能说明

`research` 通过阅读能提供答案的来源来回答问题，然后在仓库中留下带引用的 Markdown 文件。它只使用**[一手资料](https://www.aihero.dev/ai-coding-dictionary/primary-source)**：官方文档、源代码、规格说明、第一方 API。它会将每项声明追溯到实际来源，因此只要能访问 API 自身的文档，就不会转述博客文章对 API 的介绍。

它不会在对话中直接回答你。它会在仓库保存一个文件，放在仓库已有的笔记位置，并为每项声明添加链接。你会得到可以查看、交给其他代理或丢弃的文档，而不是一份在[会话](https://www.aihero.dev/ai-coding-dictionary/session)结束后就消失的答案。

## 适用情形

输入 `/research`，或当任务变成阅读资料时由[代理](https://www.aihero.dev/ai-coding-dictionary/agent)自动调用。

如果接下来的工作是从当前工作目录以外的来源*查明事实*(第三方 API 的行为、规格说明规定的内容、版本声明是否正确)，而你不希望自己停下当前会话来阅读资料，就使用此技能。根据需要选择技能：

| 你需要什么 | 使用方式 |
|---|---|
| 决策正在等待某个外部事实 | `research` |
| 希望通过访谈与你共同作出决定 | [grilling](https://aihero.dev/skills-grilling) |
| 将架构决策持久地写入 `GLOSSARY.md` 和 ADR | [grill-with-docs](https://aihero.dev/skills-grill-with-docs) |
| 确认某种方法在代码库中是否有效 | [prototype](https://aihero.dev/skills-prototype) |
| 计划太大，无法在单个会话中处理 | [wayfinder](https://aihero.dev/skills-wayfinder) |

`research` 和 `grill-with-docs` 的分界是结果的**保存期限**。Research 产出短期事实，例如本周这个库使用什么身份验证机制。ADR 记录的是要长期保留的决策。如果要生成的内容属于决策而非事实，那就是[讨论决策](https://www.aihero.dev/ai-coding-dictionary/grilling)，不是研究。

## 委派阅读工作

阅读工作会由**后台代理**执行。它会在你继续工作的同时，将每个声明追溯到一手资料，写入一个 Markdown 文件，并向你报告。研究是委派出去的阅读工作，而不是外包思考。你会得到可以用于讨论、规划或设计的文档，但仍然由你作出决定。

没有任何内容阻止后台代理再启动自己的后台代理。这是此技能有记录以来最严重的问题。

文件保存位置由仓库决定，不由技能决定。它会遵循现有笔记惯例。如果没有惯例，就选择合理位置并告诉你。每次运行只写入一个文件。

## 常见问题

**它又启动了第二个研究代理。这是预期行为吗？**

不是。这是一个尚未解决的问题，见[issue #530](https://github.com/mattpocock/skills/issues/530)。技能要求调用方启动后台代理，但没有限制代理类型。因此调用方会启动具有 `Agent` 工具和相同指令的 `general-purpose` 代理，后者又照做一次。一位报告者测得，单次研究任务在三个重叠运行中花费约 450k 个[token](https://www.aihero.dev/ai-coding-dictionary/token)，重复运行的代理还在半小时后完成，而用户看不到它。Claude Code 之外也会发生。用户确认在 Codex 中使用 GPT-5.6-sol 时也会出现同样的嵌套。目前没有正式发布的修复办法。有人在自己安装的副本中添加一行，要求已经是[子代理](https://www.aihero.dev/ai-coding-dictionary/subagent)的代理自己完成工作。这有帮助，但它只是一条指令，不是结构性修复。调用技能后，请查看后台任务列表并停止重复任务。

相反的问题也会发生。如果你的全局指令禁止代理再次委派工作，后台代理就会拒绝任务，而技能不会做任何事，也不会告诉你。

**文件应该放在哪里？是否应该提交？**

技能会将文件放到仓库已有的笔记位置，不提供其他建议。社区意见基本一致：保留 ADR，不保留研究文件。某个 Discord 讨论最清楚地表达了这一点："保留 ADR。其他内容在完成后归档或删除。否则就会成为工作残留，而且如果它偏离规格说明或研究结论，未来读取仓库时还可能受到干扰。"研究文件记录的是撰写当天成立的事实，因此过时的研究文件比没有文件更糟。总体而言，这些文件不应放进 Git，也没有标准保存位置。有人会使用 Obsidian、独立知识仓库或 issue tracker。

**什么才算"高可信度"的一手资料？由谁判断？**

由[模型](https://www.aihero.dev/ai-coding-dictionary/model)判断。技能列出符合要求的来源**类型**(官方文档、源代码、规格说明、第一方 API)，但没有允许清单、域名限制或核查流程。这是此技能首次提出时最强烈的反对意见，至今没有人公开回答："五个研究子代理如果都查垃圾来源，只会更快给出五份自信但错误的答案。你如何判断什么属于高可信来源？"唯一的保护措施是每项声明后面的引用。随机检查两三项。如果它们指向介绍资料的摘要，而不是原始资料，这次运行就失败了。

**后续会话会复用早期运行的研究结果吗？**

不会。没有任何机制会自动加载以前的研究文件。文件会留在仓库里，直到有人或某项技能引用它。早期设计受到的最强质疑是："价值在于 Markdown 文件变成代理之后会重新读取的上下文，而不是抓取资料本身。只写一次、再也不读的文件不过是精致的搜索结果。"发布的技能没有解决此问题。实际上，只有你自己把文件传递到后续步骤中，它才有用，例如将它附到规格说明中、在讨论过程中引用，或让[工单](https://www.aihero.dev/ai-coding-dictionary/ticket)指向它。

**为什么不直接让代理阅读文档？**

可以这样做。此技能取代的原有做法就是两行提示，明确要求代理这样做。此技能提供了提示无法提供的两点。首先，它在后台运行，因此会话的[上下文](https://www.aihero.dev/ai-coding-dictionary/context)保持干净。其次，每次都遵守一手资料限制并输出带引用的文件，而不是取决于你如何撰写提示。与[harness](https://www.aihero.dev/ai-coding-dictionary/harness)自带的深度研究模式相比，两者的区别在于文件和一手资料规则，而不是搜索方式。如果一个两行提示足以回答小问题，就使用两行提示。

**它什么时候停止阅读？**

技能没有停止条件。由此引起两种看似相反、根源却相同的抱怨：代理钻研得太深，或广泛覆盖主题却漏掉关键细节。一位实践者说："深度研究技能有时研究得太深。而要求代理研究通常会漏掉关键细节。"你必须设定范围。范围狭窄且有明确答案的问题(一个 API、一项行为、一条版本声明)会比"研究 X"得到好得多的结果。

**`/wayfinder` 创建了研究工单。我需要自行解决它们吗？**

不需要，现在它会自动处理。在 v1.1 之后尚未发布的更改中，规划会话会为每个研究工单启动一个 `/research` 子代理，并行执行。每个代理都会在一次性 `research/<name>` 分支中记录发现，并从工单留下[上下文指针](https://www.aihero.dev/ai-coding-dictionary/context-pointer)。研究工单是 wayfinder 每会话处理一个工单规则的唯一例外，因为这些工作是[无人值守](https://www.aihero.dev/ai-coding-dictionary/afk)的：不需要等待你。一个已知问题是，之后删除分支会让工单中的上下文指针失效。

## 判断是否有效

- 你自己的会话会继续运行。如果你坐着看代理阅读资料，就说明没有发生委派。
- 恰好出现一个新的后台任务。第二个名称几乎相同的任务就是嵌套问题。
- 仓库现有笔记目录中出现一个新的 Markdown 文件，代理会告诉你路径。
- 文件中的每个声明都带有链接，随机打开其中两个会转到官方文档、规格说明或源代码文件本身，而不是某人的二手文章。
- 只阅读文件，你就能作出原本无法作出的决定，而无需自己再去查找来源。

## 它在工作流程中的位置

`research` 是可单独随时调用的技能。它为思考类技能提供资料，不属于构建流程链的一步。你需要将它的文件**带入**后续流程。[grilling](https://aihero.dev/skills-grilling) 和 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 可以根据已知事实提出更有针对性的问题；[to-spec](https://aihero.dev/skills-to-spec) 可以据此综合规格说明。[wayfinder](https://aihero.dev/skills-wayfinder) 是唯一会直接调用它的技能：它会为计划图中的每个研究工单启动 `/research` 子代理。完整计划图请参阅 [ask-matt](https://aihero.dev/skills-ask-matt)。
