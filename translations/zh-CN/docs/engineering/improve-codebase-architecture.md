## 功能说明

`improve-codebase-architecture` 调查代码库中的**加深模块机会**。这些位置目前的模块较浅(接口与它隐藏的内容几乎一样复杂)，但可以变成深层模块。此技能会将发现写入独立 HTML 报告，然后通过[深入讨论](https://www.aihero.dev/ai-coding-dictionary/grilling)流程与你研究选中的候选项。

它绝不会修改代码。整个运行只会产生一段对话，以及一个保存在操作系统临时目录中的 HTML 文件。之后，你会在独立的[会话](https://www.aihero.dev/ai-coding-dictionary/session)中通过正常构建流程进行重构。它是调查工具，不是重构工具，因此你可以在尚未准备好修改的代码库上运行。

两项筛选规则可以避免报告变成通用的清理建议。第一，每个候选项都必须通过**删除模块检验**：如果删除该模块，复杂性会被移到更简洁的接口之后，还是会散布到各个调用方？只有第一种情况会生成卡片。第二，除非你指定某个区域，否则此技能会先阅读近期提交记录，并重点扫描经常更改的路径。加深无人触碰的代码不会带来回报。

## 适用情形

你需要输入 `/improve-codebase-architecture` 调用此技能；[代理](https://www.aihero.dev/ai-coding-dictionary/agent)不会主动调用。

它不是主要构建循环的一步。你可以定期运行它，安排更多能改进代码库的工作。以下四种情况常会使用它：

| 情况 | 使用方式 |
|---|---|
| 日常维护 | 每隔几天或有空时运行，避免功能开发期间结构逐渐退化。 |
| 大型构建之前 | 将[规格说明](https://www.aihero.dev/ai-coding-dictionary/spec)交给它，并询问"怎样能让这项更改变得简单？"这是最有效的提示。 |
| 棕地代码审查 | 在大型、无结构或[随性编码 (vibe coding)](https://www.aihero.dev/ai-coding-dictionary/vibe-coding)的仓库上运行，了解当前结构。 |
| 遗留代码测试工作 | 编写难以测试的代码之前，先找出缺失的接缝。 |

与相近技能的区别：

- 已经选定要设计的单个模块时，使用 [codebase-design](https://aihero.dev/skills-codebase-design)。本技能负责寻找模块，`codebase-design` 负责设计模块。
- 整项工作太大，无法在一个会话中完成时，使用 [wayfinder](https://aihero.dev/skills-wayfinder)。
- 某项具体功能损坏时，使用 [diagnosing-bugs](https://aihero.dev/skills-diagnosing-bugs)。如果它发现真正问题是没有适合锁定错误的接缝，就会将你引回本技能。

## 前置条件

运行不需要任何前置条件。如果存在 `GLOSSARY.md` 或 `docs/adr/` 下的 ADR，技能会阅读它们，并使用领域自己的名词。这样，候选项会称作"加深 Order 接收模块"，而不是"重构 FooBarHandler"。

它会写入两个位置。报告写到仓库以外的 `<tmpdir>/architecture-review-<timestamp>.html`。在深入讨论的过程中，它会向 `GLOSSARY.md` 添加术语或明确术语；如果文件不存在则会创建。它还会提议将被拒绝的候选项记录为 ADR，以免未来运行时再次提出。

## 深度，以及如何在报告中寻找

此技能基于一个概念：**深度**。深层模块将大量行为置于简洁且稳定的接口之后。浅层模块通过接口暴露其实现，接口和底层代码几乎一样宽。报告会寻找三类浅层结构：

- 仅为便于测试而提取纯函数，但真正的错误存在于调用方的使用方式中(缺少**局部集中度**)。
- 内容跨越其**接缝**泄漏的模块。
- 无法在不打开五个文件的情况下理解的概念。

针对每一类问题，报告会提出可以解决问题的加深方案。

每个候选项都以卡片呈现，其中列出相关文件、摩擦点、通俗易懂的解决方案、以**局部集中度**和**调用方收益**说明的好处、修改前后的图示，以及建议强度徽章。

| 徽章 | 对你的含义 |
|---|---|
| `Strong` | 删除模块检验明确通过，而且摩擦真实存在。认真考虑这些候选项。 |
| `Worth exploring` | 加深方案合理，但回报取决于代码后续将如何变化。 |
| `Speculative` | 为完整起见而纳入。大多可以忽略。 |

报告以**首要建议**结尾，指出最适合首先处理的候选项。之后技能会停止并询问你想深入探讨哪一项。此时你尚未决定任何事情，也没有更改任何代码。

## 选定候选项之后

选定候选项后，会启动针对该候选项的[讨论决策](https://aihero.dev/skills-grilling)流程。讨论约束、接缝后放置的内容、哪些测试仍然有效，以及加深后的接口应该是什么样子。讨论结果是一项决策，而不是差异。从这里开始应用正常流程：将决策交给 [to-spec](https://aihero.dev/skills-to-spec)，然后交给 [to-tickets](https://aihero.dev/skills-to-tickets)，最后交给 [implement](https://aihero.dev/skills-implement)。

## 常见问题

**它围绕一个想法追问了我一小时，却没有展示其他方案。可以关闭追问吗？**

可以。调用时说明"不要盘问我，只展示报告"。这是此技能最常见的抱怨。一位用户曾觉得它"方便地提供了彻底的改进分析"，但加入深入讨论流程后认为它"几乎无法使用"。在他们的会话中，它只提出一个方案，然后问了"几十个或上百个问题"。设计意图是先生成报告，再围绕你选定的候选项展开深入讨论。但能力较弱的[模型](https://www.aihero.dev/ai-coding-dictionary/model)会直接围绕第一个想法开始访谈。该讨论中的结果因模型不同而差异很大。此问题仍未解决，技能也没有记录关闭深入讨论模式的方法。

**报告打开后只有没有样式的原始 HTML，也没有图示，发生了什么？**

报告通过 CDN 加载 Tailwind 和 Mermaid，因此打开报告时需要联网。如果有内容阻止这些脚本加载，页面就会失效，却不显示错误。在有人报告的情况中，安全钩子要求使用 SRI 哈希。代理添加了哈希，但 CDN 提供给浏览器的内容与用于计算哈希的 `curl` 所取得的内容不同，因此浏览器阻止脚本运行。脱机和受限制的环境也会有相同问题。代理无法发现问题，因为它从未渲染页面。作为替代方案，可以要求使用内联 CSS 和手工制作的 SVG 图示，而不是通过 CDN 加载。目前此问题仍未解决。

**报告列出了十二个候选项。我应该在同一会话中逐一处理，还是为每项创建新会话？**

每个会话处理一个候选项。如果在同一场对话中处理多个候选项，[上下文窗口](https://www.aihero.dev/ai-coding-dictionary/context-window)会同时装入报告、深入讨论过程、领域模型修改和代码更改。报告只是一个临时文件，因此应带走候选项，不要带走文件。选择一个候选项，深入讨论，并将决策交给 `/to-spec`。其余候选项可以转成以后单独处理的[工单](https://www.aihero.dev/ai-coding-dictionary/ticket)。将选中的改进写入规格说明，不要直接实现。人们经常询问此问题，但技能本身没有记录工作流程。

**我应该怎样向它说明需求？**

告诉它接下来要构建什么。如果即将进行大型构建，就将规格说明交给它，并询问"怎样能让这项更改变得简单？"没有提示时，它会自行查找热点。这适合日常维护，但明确方向会让报告更有可操作性。

**它适用于大型遗留代码库吗？**

部分适用。对于结构缺乏一致性的大型现有代码库，它很有用；在任何一次性结构设置完成后，也建议使用它进行维护。不过，项目失控的用户报告说它"帮了一点忙，但仍然不够"。一位维护八年历史遗留代码库的开发者称，模型一直绕圈；而同一技能在结构整洁的仓库中却会生成清晰任务图。目前还没有专门处理这类问题的 `/refactor` 技能。如果代码库没有共用词汇，先运行 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 创建一套词汇。这通常会显著改善本技能的输出。

**这和 `/codebase-design` 有什么不同？**

`/codebase-design` 是参考资料，不负责驱动会话。它提供词汇(模块、接口、深度、接缝、适配器、调用方收益、局部集中度)，本技能会使用这些词汇。如果你直接将 `/codebase-design` 交给新代理作为任务，会出现已知问题。它没有可遵循的流程，代理就会自行编造流程，重新探索代码，并运行很长时间才会询问你。运行本技能，让它使用 `/codebase-design`。

**它会告诉我代码库没问题吗？**

很少如此，开始之前要了解这一点。技能的目标是报告发现，因此通常会生成候选项，而不是得出没有问题的结论。使用强度徽章修正此偏向。如果报告中的每项候选项都是 `Speculative`，就表示技能没有发现问题。

**它适用于 Codex 或其他运行环境吗？**

部分适用。探索步骤直接指定 Claude Code 的 `Agent` 工具和 `subagent_type=Explore`。没有该工具的[运行环境](https://www.aihero.dev/ai-coding-dictionary/harness)可能会跳过并行探索，而不是使用等效工具。技能仍会运行，但扫描就不那么彻底。有人提议改写成与运行环境无关的版本，但尚未合并。

**我怎样才能在 TypeScript 中实际实现深层模块？**

技能没有提供好的答案。很多人要求增加包含具体文件和模块布局的 `TYPESCRIPT.md`，用于落实这些原则，但目前不存在此文档。技能会告诉你加深应放在哪里，以及接缝之后应包含什么。你必须自行将这些想法转化为程序包或目录结构。

## 判断是否有效

- 候选项使用领域概念，而不是发明的类名称："Order 接收模块"，而不是"FooBarHandler"。
- 候选项涉及你最近编辑过的文件，而不是无人触碰的仓库区域。
- 运行期间没有代码更改。唯一新增文件是临时目录中的 HTML 报告。
- 生成报告后就停止，并询问你想选择哪个候选项，不会自行继续。
- 每张卡片都从局部集中度或调用方收益角度说明收益，并指出哪些测试会更简单，而不只是声称"代码更干净"。
- 你因为长期原因拒绝候选项时，它会提议记录 ADR，以免下次运行时重新提出。

## 它在工作流程中的位置

`improve-codebase-architecture` 用于**定期维护**。你每隔几天在流程链之外运行它，安排工作，而不是直接执行工作。相邻技能包括：

- [codebase-design](https://aihero.dev/skills-codebase-design) 提供每个候选项都要使用的深度和接缝词汇。
- [grilling](https://aihero.dev/skills-grilling) 在你选定候选项后梳理决策过程。
- [domain-modeling](https://aihero.dev/skills-domain-modeling) 在作出决策时维护 `GLOSSARY.md` 和 ADR。

它的输出是一项想法，会通过 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 或 [to-spec](https://aihero.dev/skills-to-spec) 返回主要构建流程。主流程末尾的对应技能是 [retro](https://aihero.dev/skills-retro)。本技能改进代理要处理的代码；`retro` 则在构建结束后改进外围环境(检查、标准、指导文件)。如果不确定某种情况适合什么技能，[ask-matt](https://aihero.dev/skills-ask-matt) 会在整组技能中进行引导。
