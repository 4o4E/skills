## 功能说明

`wizard` 会生成交互式 Bash 脚本，逐步引导用户完成手动流程：连接第三方服务、运行一次性迁移，或将项目从状态 A 转换到状态 B。它会打开每个网址，说明需要点击和复制的内容，收集得到的信息，并将其写入 `.env` 文件和 GitHub Actions 密钥。

[代理](https://www.aihero.dev/ai-coding-dictionary/agent)负责编写脚本，但绝不会运行它。由你在自己的机器上运行。向导是程序，不是操作说明列表。脚本会按顺序执行每一步，并保留你输入的值。你只需点击、粘贴并按 Enter。

## 适用情形

你可以输入 `/wizard`，代理也可以自行调用。当代理遇到一个必须由你执行的步骤(例如代理无法创建的密钥或无法点击的控制面板)时，它会为你生成向导，而不是将说明写进聊天中，以免说明之后滚动消失。

接下来的阻塞事项需要你浏览控制面板时，使用此技能：

| 情况 | 向导会做什么 |
|---|---|
| 新开发人员必须先配置六个服务，应用程序才能启动 | 按顺序打开每个控制面板，收集密钥，并写入 `.env` 和 CI |
| 一次性迁移要求按特定顺序切换设置 | 在确认关卡后依次执行不可逆步骤 |
| 项目必须从状态 A 一次性迁移到状态 B | 引导完成转换，并报告无法执行的内容 |
| 你正准备把操作步骤写入 README | 改为编写可执行版本；某个步骤过时后，脚本会明确失败 |

不要用它来*决定*要构建什么；应该使用 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 和 [to-spec](https://aihero.dev/skills-to-spec)。

## 前置条件

生成向导不需要前置条件。生成的向导使用 Bash 运行，在某个阶段要设置 GitHub 密钥或变量时使用 `gh`。如果缺少 `gh` 或没有通过身份验证，运行不会失败。相应阶段会显示警告，结束摘要会告诉你需要手动设置什么。

## 阶段

**阶段**是在单个屏幕上完成的一项明确任务。脚本会在阶段之间清空终端，因此某阶段超出一屏时，滚出屏幕的内容就会消失。你需要按依赖顺序编写阶段，并设置 `TOTAL_STAGES` 来驱动进度显示。

[技能](https://www.aihero.dev/ai-coding-dictionary/skill)会先界定流程，再编写脚本。它会先阅读仓库，而不是贸然提问：`.env*`、`docker-compose*`、框架配置，以及 `.github/workflows/` 中所有 `secrets.*` / `vars.*` 引用。这些引用对应的每个值都是向导必须生成的内容。然后它会按顺序向你展示阶段列表并请你确认。只有在你确认后，它才会为每个阶段规划用户应遵循的准确路径("控制面板 → 开发者 → API 密钥 → 显示测试密钥 → 复制")。不知道当前用户界面时，它会询问你或检查文档，而不是编造点击步骤。

界定流程时会决定每个收集到的值应放在哪里：

| 目标位置 | 适用情形 |
|---|---|
| 只写入 `.env` | 本地开发需要，CI 不需要 |
| GitHub 密钥 | CI 读取，而且内容敏感 |
| GitHub 变量 | CI 读取，而且内容公开 |
| 同时写入 `.env` 和 GitHub 密钥 | 本地开发和 CI 都需要 |
| 不写入任何位置 | 此阶段只是纯操作：切换开关、升级计划 |

## 模板已解决交互体验

[模板](https://github.com/mattpocock/skills/blob/main/skills/engineering/wizard/template.sh)已实现完整使用体验：显示进度和剩余时间、提供确认关卡、跨平台打开网址(包括 WSL)、隐藏密钥输入、幂等地更新 `.env`、写入 `gh secret` / `gh variable`，并在结束时总结所有无法处理的内容。`STAGES` 标记上方的内容是固定函数库，在每个向导中都相同，绝不手动编辑。由于函数库不会变化，每个向导的行为都相同。每个向导唯一需要做的工作是界定流程并编写阶段。

编写向导的代理不会端到端运行脚本，因为脚本会打开浏览器并等待用户输入。代理会进行静态检查：运行 `bash -n`，如有 `shellcheck` 则运行它，并逐项追踪值是否写入界定流程时指定的位置，以及每个 `set_secret` 名称是否与 CI 中实际的 `secrets.*` 引用一致。因此，第一次运行由你完成，而这次运行就是测试。

## 默认只用一次

| 你的需求 | 脚本处理方式 |
|---|---|
| 一次性迁移、个人设置、绝不会重复的转换 | 保存到临时位置或 `scripts/`，运行后删除 |
| 仓库下一位使用者也需要的设置流程 | 提交脚本并从 README 链接，让他们运行脚本，而不是再次询问代理 |

## 常见问题

**我的 API 密钥会进入模型上下文吗？**

不会。代理编写脚本，但不运行脚本。你自行运行脚本，它会在终端中隐藏输入密钥，并直接将密钥写入 `.env` 或 `gh secret`。向导是 CLI，模型不会连接它。但这只适用于向导在运行时收集的值。如果你在界定流程时把密钥粘贴到聊天中，它就会像其他粘贴内容一样进入[上下文](https://www.aihero.dev/ai-coding-dictionary/context)。

**我能返回上一阶段并修正输错的值吗？**

运行期间不能返回。向导没有后退按钮，阶段会一直向前运行；如果第 3 阶段的答案有误，就按 Ctrl-C 并重新运行。重新运行成本很低，因为已写入 `.env` 的值会作为默认值再次提供。正确的阶段按 Enter 即可，只有错误值需要重新输入。用户在技能发布周就提出了此要求，目前仍未解决："很喜欢！不过，能不能返回去修改之前输入的内容？"

**它知道我已经完成哪些设置吗？**

部分知道，掌握的信息没有发布时的反馈所暗示的那么多。它会先读取仓库(你的 `.env` 文件、`docker-compose`、框架配置、CI 中的 `secrets.*` 引用)，因此会界定缺少哪些值，而不是像 README 一样从头开始。它不会查询第三方服务。如果你的 `.env` 中已有密钥，向导会重新提供该值，按 Enter 就会保留；如果你已经创建 Stripe 账户但没有保存密钥，向导仍会引导你进入控制面板获取密钥。

**它在工作流程中处于深入讨论和规格说明之后吗？**

没有固定位置。它是独立技能，不是流程链的一步。常见猜测是 `/grill-with-docs → /to-spec → /wizard`，这套顺序没有问题，但触发条件是出现手动流程，因此任何时间都可能触发：开始前、构建途中，或发布很久以后。它也能用于发现问题。界定流程时会在你承诺工作前找出隐藏前置条件，例如你之前没想到的三个 API 密钥。

**它能在 Claude Code 之外使用吗？**

生成的脚本可以。它是原生 Bash，不论由哪个[运行环境](https://www.aihero.dev/ai-coding-dictionary/harness)生成，都能以相同方式运行。技能本身可以由模型调用，因此在所有平台都会显示：在 Claude Code 中输入 `/wizard`，在 Codex 中输入 `$wizard`，或直接描述你遇到的设置问题。允许模型调用也能避开[议题 #693](https://github.com/mattpocock/skills/issues/693)中的问题：Claude 桌面和网页应用会从[模型](https://www.aihero.dev/ai-coding-dictionary/model)的技能列表中移除*用户调用*的技能，并报告技能未安装。

**它以前不是用户调用的技能吗？**

以前是。现在它可以由模型调用，因此代理遇到必须由你执行的步骤时会主动调用。以前能做的事情仍然可以做。模型调用让代理和你都能调用该技能，因此 `/wizard` 的行为仍与以前相同。这项更改解决了一种失败情况。以前，代理在构建期间遇到凭据阻塞，会在聊天中列出六个编号步骤让你手动操作。现在它会编写向导。

**它以前位于 `in-progress/`。现在去哪里了？**

从 v1.2 开始，它位于 `engineering/`。它已从测试阶段类别中毕业，现在随插件发布，因此会与其他正式提供的技能一起安装，而不需要单独安装。正式发布时，它的行为没有改变。

## 判断是否有效

- 任何脚本出现之前，它先向你展示有序阶段列表及每个阶段产生的值，并请你确认。
- 每个网址都会先打开，然后才询问该页面上的值。它绝不会要求你粘贴尚未引导你获取的内容。
- 密钥以隐藏方式输入，不会在终端滚动记录中显示任何敏感信息。
- 每个阶段都能放进一个屏幕。你仍然需要的内容不会滚出屏幕。
- 按 Ctrl-C 并重新运行后，它能从中断处继续，并将已保存的值作为默认选项提供。
- 结束页面会列出它写入的内容，并单独列出它无法执行、需要你手动完成的事项。

## 它在工作流程中的位置

`wizard` 是可随时调用的独立技能，位于自动化操作需要停止、等待用户点击的位置。它最相近的技能是 [setup-matt-pocock-skills](https://aihero.dev/skills-setup-matt-pocock-skills)，两者都用于让仓库进入可工作状态。前者配置这组技能，`wizard` 则为其他内容生成设置流程。它也可以和 [implement](https://aihero.dev/skills-implement) 配合使用：构建工作完成某项功能后，如果该功能需要凭据或人工切换流程，向导就会覆盖只有用户才能执行的步骤。如果不确定当前情况适合哪种技能，[ask-matt](https://aihero.dev/skills-ask-matt) 会为你引导。
