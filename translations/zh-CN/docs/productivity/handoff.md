## 功能

`handoff` 会将当前对话整理成一份**交接文档**：一个 Markdown 文件，写入操作系统的临时目录而不是工作区，供新的[代理](https://www.aihero.dev/ai-coding-dictionary/agent)读取并接手工作。

它提供的是**可移植性**，而不是压缩，因此此技能的适用范围比名称听起来更窄。只有工作需要_转移_时才需要文件：转到新的[harness](https://www.aihero.dev/ai-coding-dictionary/harness)、新目录、同事手中，或你想分出去的附带任务。如果没有东西需要转移，就不需要交接。在同一[会话](https://www.aihero.dev/ai-coding-dictionary/session)中继续工作、使用 `/clear`、[子代理](https://www.aihero.dev/ai-coding-dictionary/subagent)和 `/compact` 都能处理一般的阶段结束情况，而且 `/compact` 比此技能适用得更多。

## 何时使用

输入 `/handoff` 即可调用；代理不会自行调用。说明下一次会话的用途，技能就会据此撰写文档。

只有以下四种情况会触发使用：

| 情况 | 为何需要文件 |
| --- | --- |
| 更换运行环境(Claude → Codex) | 新的运行环境看不到原来的[上下文](https://www.aihero.dev/ai-coding-dictionary/context) |
| 移到另一个目录或代码仓库 | 移动原型目录是常见情形 |
| 把工作交给同事 | 对方需要可以阅读的内容 |
| 在工作阶段中发现附带任务并分出去 | 你继续工作，第二个代理接手分出去的任务 |

其他情况(同一运行环境、同一目录、[追问](https://www.aihero.dev/ai-coding-dictionary/grilling)结束并开始实施)都使用 `/compact`。[ask-matt](https://aihero.dev/skills-ask-matt) 在每个阶段边界处提供包含全部五种选项的有序流程图。

## 分出附带任务是用户常忽略的用途

技能的描述听起来像是恢复会话：写下摘要，在此处结束，然后去别处继续。这样理解时，它看起来像较差的 `/compact`，所以人们会跳过它。最值得了解的是分出附带任务的用法。你**留在当前会话**，把累积的上下文复制给第二个并行工作的代理。

[prototype](https://aihero.dev/skills-prototype) 会使用这种绕行方式。你正在深入讨论设计时，遇到一个只有运行代码才能解决的问题，但不想用已经建立起来的对话去查明。将工作交接给原型会话，取得答案，再把答案交回，并在原始对话中引用。工作会来回传递两次，原始对话仍然有效，你也不需要重新解释任何内容。

阶段边界处的五种选项中，有三种分别保留不同内容：`/compact` 保留你的意图，`/clear` 什么都不保留，`/handoff` 保留工作转移到其他地方的能力。

## 会转移什么，不会转移什么

文档会记录当前仍在进行的工作(正在处理什么、原因、下一步)，并加入一个**建议使用的技能**部分，列出下一位代理应使用的技能。此技能会在写入文件前删去机密信息。

文档刻意不包含已经记录下来的内容。它会用路径或 URL 引用规格说明、计划、ADR、issue、提交和差异，不会复制它们。这样能让文件保持简短，也能让已确定的细节只留在一处，避免两个副本逐渐产生差异。

## 常见问题

**应该交接还是压缩？**
除非有东西要转移，否则使用 `/compact`。如果仍在处理同一任务，那就是压缩，不是交接。当运行环境和目录不变，而且你还要继续参与时，阶段边界流程通常会以 `/compact` 结束。`/handoff` 不会写出更好的总结。它的优势是产生一个可以带到 `/compact` 无法到达之处的文件。

**压缩、清除和交接有什么实际区别？**
它们分别保留不同内容。`/compact` 会压缩当前上下文并在新的窗口中继续，因此你的意图会保留下来。`/clear` 会清空窗口并从头开始。当之前的所有内容都不再需要时，这是正确做法；如果内容仍有用，就无法撤销。`/handoff` 会写出可移植文件，因此工作可以随你转移到其他地方。这三种方式都会把**[一手资料](https://www.aihero.dev/ai-coding-dictionary/primary-source)**(实际发生的对话)变成**[二手资料](https://www.aihero.dev/ai-coding-dictionary/secondary-source)**(对话摘要)。只有继续当前会话不会这样做，所以你应该先排除这一选项。

**交接文件放在哪里？**
它会写入临时目录，这是用户最常报告的问题。技能会将临时目录解析为 `$TMPDIR`，否则使用 `/tmp`(Windows 使用 `%TEMP%`)，但路径可能很长。请让代理告诉你路径，并在继续之前保存它。临时目录是刻意选择的，因为交接文档是正在转移的文件，不是需要长期维护的产物。临时文件也不可靠，下一条会解释原因。

**我的交接文件在会话之间消失了。**
某些环境会在会话之间清除临时目录(据悉 Codex 就是这种情况)，重新启动也会清空 `/private/tmp`。如果下一次会话不是一小时内启动，或要在另一种运行环境中启动，文件写入后应立即自行复制到持久位置。文档_引用的文件_也一样：如果交接文档引用了临时目录中的其他文件，下一位代理就无法打开它们。

**实际要怎样把工作交给下一位代理？**
打开新的会话并提供文件路径：让代理阅读文件，然后继续处理。请提供文件路径，不要把摘要粘贴到 shell 命令中。如果将包含反引号或 `$(...)` 的摘要插入 `claude "<summary>"`，shell 会破坏其中内容。通常的结果是内容被静默截断，而不是出现错误，因此新代理得到的说明不完整，你也不会收到任何提示。

**它与 `/branch`、`--fork-session` 或内置的 `/handoff` 相同吗？**
这些功能相似，但不完全相同。`/branch` 不是此处发布的技能；`/handoff` 是规范名称。分支会继承完整的上下文副本；此技能会根据你说明的下一项任务，生成一份有针对性的精简文档。目的地与分支功能适用条件相同(同一台机器、同一运行环境、同一目录)时，使用分支更省事。如果目的地无法使用分支，文件会是更好的选择。

**什么内容应该放进 `CLAUDE.md`？**
问自己下个月它是否仍然成立。`CLAUDE.md` 是项目的长期上下文，每次会话都会加载，不论内容是否相关。交接文档只描述一项仍在进行的工作，工作完成后就失去用途。如果你需要反复解释一项事实，就把它放进 `CLAUDE.md`。尚未完成的任务则应该放进交接文档。

**文档记录了事情是什么，却没有记录原因。**
这是一项合理的批评，用户经常反映这一问题。有两种方法可以改善：在调用时提供参数说明下一次会话的具体目标，促使技能保留针对该任务的推演细节，而不是将信息过度压缩成粗糙摘要；同时要留心那些未经会话核实却语气断定的表述(例如"X 尚未构建"或"Y 已完成")。下一位接手的代理会直接盲信文档而不加复查，因此将主观推测写成既成事实，会给后续工作埋下错误前提。交接前请务必通读文档，将未经求证的结论改写为客观中立的描述。

**为什么它是技能，而不是斜线命令？**
两种方式都可行，适用于不同情况。作为技能，它会和这里所有其他内容使用相同的安装路径发布和更新，因此可以共享。阻止代理自行调用它的是 frontmatter，而不是调用机制。

## 判断是否有效

- 文档只占整个对话的一小部分，规格说明、issue 和差异都以路径和 URL 出现，而不是复制的文字。
- 即使没有打开原始会话，你也能直接阅读文档并知道下一步该做什么。
- 新代理会开始工作，而不是要求你重新解释设置。
- 在分支情况下，你返回时原始会话没有改变。
- 建议使用的技能部分列出了你自己也会使用的技能。
- 文档中没有密钥、访问令牌或密码。

## 适用范围

`handoff` 是一个**可随时使用的独立技能**。它处理的是会话之间的交接，不属于构建流程。它的适用范围较窄，在阶段边界的其他四种选项中，使用频率也较低。它最接近的技能是 [prototype](https://aihero.dev/skills-prototype)，因为原型项目位于独立目录，而来回传递正是此技能适用的情况。如果你在阶段边界处不确定应该继续、清除、交接、委派还是压缩，[ask-matt](https://aihero.dev/skills-ask-matt) 提供了安排这五种选项的流程图，也能引导你使用其他相关技能。
