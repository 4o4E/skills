## 功能

`to-questionnaire` 会把你无法独自决定的事项转成一份**问卷**：将 Markdown 文档交给掌握你所缺信息的一个人，让对方异步填写，或在会议中与你共同填写。

它只会追问**如何发送**，绝不追问主题。访谈主题毫无意义，因为你正是由于不熟悉主题才要询问别人。因此它只询问两件你总能回答的事(问卷要发给谁，以及你需要对方提供什么)，并让文档中的每个问题都针对这两者之间的**信息差**。

## 何时使用

输入 `/to-questionnaire` 即可调用；[代理](https://www.aihero.dev/ai-coding-dictionary/agent)不会自行调用。

如果某项决定卡在另一个人掌握的知识上，就使用此技能：例如客户、领域专家、负责业务规则的主管，或你不在同一团队的同事。应根据答案所在的位置选择技能：

| 答案在…… | 使用方式 |
| --- | --- |
| 你自己的想法中，但还不够明确 | [grill-me](https://aihero.dev/skills-grill-me) |
| 代码库中 | [grill-with-docs](https://aihero.dev/skills-grill-with-docs) |
| 别人的想法中 | `to-questionnaire` |
| 目前谁的想法中都没有，需要先有内容供讨论 | [prototype](https://aihero.dev/skills-prototype) |

常见情况是一次[追问](https://www.aihero.dev/ai-coding-dictionary/grilling)会话卡在某些问题不是由你来回答时。请在同一段对话中运行 `/to-questionnaire`，将这些问题交给对方异步回答，然后带回答案继续工作。

## 追问发送方式，不追问主题

访谈只进行两轮交流，然后就会停止。

- **问卷要发给谁？** 询问对方的角色、专业知识，以及对方与你的关系。这会决定语气和文档应包含多少背景。外部客户需要了解背景；团队伙伴则不需要。
- **你需要对方提供什么？** 询问你无法独自解决的具体决定或事实。这会成为最终文档的检查清单。你提到的每一项都会有对应的问题。

之后的工作都是撰写。技能会将文件写入当前目录下的 `to-questionnaire-<slug>.md`。不需要设置、工作区或配置。

## 文档

此文档是一份**探索问卷**，因为你缺少背景，而接收者掌握这些背景。这决定了文档的形式：

- 用一行说明问卷目的，以及它涉及的决定；另设简短的背景部分，方便完全不了解情况的接收者阅读。
- 问题按**重要程度从高到低**排列，并按主题分组，因为异步作答可能只有一次机会。
- 每个问题只包含一个想法，绝不复合；问题下方直接留出答题位置，只有在问题可能被误解时才添加_为何这很重要_一行说明。
- 明确允许对方回答"我不知道"，因为说明不确定性有用，而自信的猜测看起来就像事实。
- 最后留一个开放问题：有没有我们没问到、但应该了解的事情？

此文档刻意避免两种形式。它不是**分支式问卷**。问题是按主题分组的固定列表，不会根据 A 题答案跳过 D 题。它也不是**多收件人问卷**。一次运行只为一个人生成一份文件。

## 常见问题

**它会读取我的追问会话并提取问题吗？**
它不会把这件事作为独立步骤。此技能没有导入阶段；它会先询问发送方式，然后撰写文档。在追问后使用它有效，是因为你在**同一段对话**中运行，因此[会话](https://www.aihero.dev/ai-coding-dictionary/session)已经位于[上下文](https://www.aihero.dev/ai-coding-dictionary/context)中，撰写时可以使用这些内容。如果你在新会话中启动，它就不知道之前的追问内容；当它询问"你需要对方提供什么"时，你必须重新说明主题。

**缺少的答案分别由不同的人掌握。它能按收件人拆分吗？**
不能。第一步会要求你指定_一个_收件人，技能会让整份文档的语气和背景都针对这个人。如果三个人分别掌握答案的三个部分，就针对每个人各运行一次。有人要求制作一份按专业领域或职务分配问题的文件，但此功能没有发布。

**问题之间有依赖关系吗？它会根据先前答案跳过某些部分吗？**
不会。我们曾经探索过依赖式问题设计，但最终没有发布。输出是一份固定文档：按照主题分组、按重要程度排列，每个问题都适用。这个设计的缺点确实存在。[模型](https://www.aihero.dev/ai-coding-dictionary/model)如果要在收到真实答案之前先规划两三个以上的问题，规划质量会很差；分支式文档更是必须在收到任何答案之前规划所有问题。

**接收者也不知道答案怎么办？**
文档会告诉对方如实说明。文档明确允许回答"我不知道"和提供部分答案。标明不确定性比猜测更有价值，因为模糊答案和自信却错误的答案，回到你的上下文中之后看起来完全相同。

**它会把问卷发送到某处吗(Slack、议题跟踪系统、电子邮件)？**
不会。它会在当前目录写入 Markdown 文件并告诉你路径。由你自行发送：粘贴到[工单](https://www.aihero.dev/ai-coding-dictionary/ticket)，放进 Slack 对话串，附加到电子邮件，或在共享屏幕上打开并当场讨论。用户已经手动采用过这四种方式。

**这不就是批量运行 `/grill-me` 吗？**
不是。`grill-me` 已经会分**轮次**提问。它会一次询问全部开放问题，再根据你的回答重新计算前沿，因此已经满足"一次给出所有问题"的需求。`to-questionnaire` 的差别在另一个方面：它关注答案在谁的脑海里，而不是问题如何呈现。要更快地自行回答问题，请使用 `grill-me`。要向别人收集答案，请使用此技能。

**我不能直接让代理做这件事，而不使用技能吗？**
可以，在技能存在之前很多人就是这样做的：建立 `OPEN_QUESTIONS.md` 文件、将电子表格发给客户，或为每个未解问题建立一张"需要更多信息"的工单。此技能提供两项帮助：访谈不会偏离主题，文档的格式也方便非技术人员填写。如果你已经有好用的固定格式，就不需要此技能。

## 判断是否有效

- 它会询问收件人和你需要的回复，然后就停止提问。如果它开始询问主题本身，技能就没有正常工作。
- 你列为"我需要对方提供什么"的每一项，都能在文件中找到相应问题。
- 问题会针对_接收者_掌握的内容，而不是照抄你自己尚未解决的问题。
- 你可以把文件交给一个未参与对话的人，对方也能知道收到问卷的原因，以及回复期限。
- 收到的答案可以作为新一轮追问的有效输入，而不会变成另一批新问题。

## 适用范围

`to-questionnaire` 是一项可随时使用的独立技能。自己所知有限，而下一步需要询问其他人时，就使用它，而不是运行另一个技能。最常见的情况是在工作流程中段，计划因为某件并非由你决定的事情而停滞。

它最接近的技能是 [grill-me](https://aihero.dev/skills-grill-me)，两者的区别在于答案由谁掌握。追问从你这里取得答案；问卷则向其他人收集答案。你可以把收到的内容交回下一轮追问，或交给 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 或 [to-spec](https://aihero.dev/skills-to-spec)，继续准备构建工作。如果不确定当前适合使用哪种技能，[ask-matt](https://aihero.dev/skills-ask-matt) 会为你指引。
