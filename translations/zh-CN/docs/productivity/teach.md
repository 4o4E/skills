## 功能

`teach` 会把你运行它的目录变成长期教学工作区，并在多次[会话](https://www.aihero.dev/ai-coding-dictionary/session)中通过简短、独立的 HTML 课程教你一个主题。

它不会根据[模型](https://www.aihero.dev/ai-coding-dictionary/model)已经知道的内容教学，而是将[模型内在知识](https://www.aihero.dev/ai-coding-dictionary/parametric-knowledge)视为不可信。在教学之前，它会寻找高可信度资源，将其记录到 `RESOURCES.md`，并在每堂课中引用这些资源。它也有[状态](https://www.aihero.dev/ai-coding-dictionary/stateful)。学习任务、资源、课程和学习记录都以文件形式保存在目录中，因此下一次会话会根据这些文件继续教学，而不是依靠上一次会话留下的内容。

## 何时使用

输入 `/teach` 即可调用；[代理](https://www.aihero.dev/ai-coding-dictionary/agent)不会自行调用。

当学习本身就是项目时，使用此技能：例如学习一门语言、一个框架、刚加入的代码库、瑜伽、着色器或证照课程。它不是用来临时解释一件事的工具。

| 你的目标 | 使用方式 |
| --- | --- |
| 用多周时间学习一个主题，并在多次会话中积累知识 | `teach` |
| 在当前会话中解释一个概念 | 直接在该会话中提问 |
| 代理刚才的消息没讲清楚，需要重新表达 | [wait-what](https://aihero.dev/skills-wait-what) |
| 打磨已有的想法，而不是获取新知识 | [grill-me](https://aihero.dev/skills-grill-me) |
| 让后台代理阅读[一手资料](https://www.aihero.dev/ai-coding-dictionary/primary-source)并留下有引用的文档 | [research](https://aihero.dev/skills-research) |
| 学习追问过程中出现的内容，同时不打断[追问](https://www.aihero.dev/ai-coding-dictionary/grilling) | 使用 [handoff](https://aihero.dev/skills-handoff) 转到教学工作区，再在那里运行 `teach` |

## 前置条件

`teach` 会创建一个目录，而不是只产出一个文件；它假设每个工作区只有一个学习任务。因此，应在你愿意专门用于单一主题的目录中运行。不要在当前工作项目中运行。另设代码仓库是最佳选择，比全局 `~/.learnings/` 目录或当前项目更合适。专用代码仓库还可以让你提交课程，这也是团队共享课程的方式。

该目录中会累积以下内容：

| 路径 | 内容 |
| --- | --- |
| `MISSION.md` | 你学习此主题的原因。所有其他文件都依赖它。如果它不存在，`teach` 首先会访谈你，直到内容确定为止。 |
| `RESOURCES.md` | 教学所用且经过审查的资源，分为知识与智慧(社群)。 |
| `lessons/*.html` | 编号课程，是主要教学形式。 |
| `reference/*.html` | 精简的速查表、算法、词汇表：供你反复查阅的文档。 |
| `learning-records/*.md` | 类似 ADR 的学习证明记录，用来决定接下来教什么。 |
| `assets/*` | 可复用组件，首先会有共用样式表，让各课程看起来像一门完整课程。 |
| `NOTES.md` | 你说明过的教学偏好和工作笔记。 |

补充说明两点。词汇表适用于大多数主题，但此技能随附了 `GLOSSARY-FORMAT.md`，而 `SKILL.md` 已不再链接到该文件，因此只有在你提出要求时才会建立词汇表([议题 #559](https://github.com/mattpocock/skills/issues/559))。所有文件都会写入运行 `/teach` 的目录。

## 存储强度，而非熟练度

思考时应使用**存储强度 (Storage strength)**这个词：它指长期记忆能力；与之相对的是**熟练度 (Retrieval fluency)**，指阅读时感觉像已经掌握的即时回忆能力，但一周后就会消失。`teach` 会通过适当难度建立存储强度：检索练习、间隔练习和交错练习。先学习知识。在这个阶段，难度会占用理解知识所需的工作记忆，对你没有帮助。之后 `teach` 会通过紧密的反馈回路训练技能；在这一阶段，难度就是工具。

两件事决定你会学到什么。**学习任务**(你学习的具体现实原因)是每一课的依据。没有学习任务，课程会变得抽象，也无法决定接下来应该教什么。`teach` 会根据学习任务和学习记录，在你的**最近发展区 (Zone of proximal development, ZPD)**内选择下一课：难度足以让你付出努力，但不会远到无法学习。

存储强度也是此技能会提出异议而不是一味同意的原因。需要**智慧**(现实中的判断力)的问题会先得到尝试性的回答，再附上可以检验答案的社群链接。技能不会让你跳过测验。有一位用户说"非常感谢"后，技能告诉他练习尚未完成。

## 课程、参考资料和组件

**课程**是一份独立的 HTML 文件，长度应当适合一次学完，内容与学习任务相关，并带来一项具体成果。课程应引用来源，建议你亲自阅读一项一手资料，并链接到同一课程体系中的其他课程和参考文档。

你很少会重新阅读某一课，却会回头查阅参考文档。因此课程的简短形式(语法表、算法、姿势顺序、词汇表)应放在 `reference/` 中，而不是埋在首次介绍它的课程里。

课程由 `assets/` 中的**组件**构成：样式表、测验部件、模拟器、图示辅助工具。默认做法是复用。代理会在撰写课程前阅读 `assets/`，并使用其中的内容。第二堂课也可能使用的新内容，应写成组件，不要嵌入课程。每个工作区的第一个组件都是共用样式表，它能让课程看起来像一门完整课程，而不是许多毫不相关的页面。

## 常见问题

**文件写到哪里了？我的文件出现在 `~/.claude/skills`。**
文件会写入你运行 `/teach` 的目录([议题 #377](https://github.com/mattpocock/skills/issues/377))。

**我要留在同一会话中，还是每一课开一个新会话？**
三种方式都可以：留在当前会话，在新会话中再次调用 `/teach`，或在同一文件夹中开启新会话。每一课都是一次独立调用。课程状态保存在文件夹中，而不是对话里。常见做法是在工作区开启新会话，并输入 `/teach next lesson for <topic>`。

**怎样知道它没有教我编造的内容？**
你不能只因为技能这样说就相信它。你需要阅读一手资料。`teach` 不够可靠，不能未经核实就信任；建立在大型语言模型上的技能也都一样。资料来源(`RESOURCES.md`、每课引用、一课一项建议阅读的一手资料)让核实课程更容易，但不能取代核实。这种问题确实发生过：一位学习 2x2 魔方的用户得到了一些无法还原魔方的编造转动步骤。遇到这种情况，请检查模型、运行环境、投入程度设置和资料来源。精确步骤的领域风险最高；输出可以立即验证的领域风险最低，例如可以运行的代码。

**测验答案总是第一个选项。**
多个用户在 Sonnet、Opus 和 GLM 上都确认了这个问题，至今仍未修复。`SKILL.md` 现在要求所有选项的词数相同。这会消除另一种线索(过去正确答案是唯一经过完整推理的选项)，但没有说明答案的位置。一个贡献者测试了针对位置的指令级修正，九堂课共三十三题的正确答案仍三十三次都出现在 A 选项([议题 #335](https://github.com/mattpocock/skills/issues/335))。因此，真正的解决方案是让 `assets/` 中的测验组件打乱答案顺序，而不是改进措辞。此功能发布之前，请忽略答案所在位置。你可以自行修改 `assets/` 目录，因此可以要求编写一个在显示时打乱答案的本地组件。

**它假设我已经知道某些内容，却使用从未定义过的术语。**
这是最常见的真实抱怨。此技能没有学习程度评估步骤。`teach` 会根据学习任务和学习记录推断你的程度，但在第一次会话中还没有学习记录。一位在 wayfinder 流程中使用此技能的用户说得很直接："它从来没有通过追问确定我的起点，所以对我已掌握的内容作了很多假设。"另一位用户说，课程使用了未定义的术语，而且介绍他们的硬件时只讲硬件能做什么，没有说明它不能做什么。有两种办法有帮助：在第一条消息中说明你已经知道什么和还不知道什么；课程程度不合适时，直接指出来，因为这项更正会成为学习记录，并影响下一堂课。增加明确的知识评估步骤仍是长期功能请求([议题 #725](https://github.com/mattpocock/skills/issues/725))，并非已发布的功能。

**它会安排间隔复习吗？它知道何时停止教学吗？**
前者不会，后者也不可靠。此技能设计课程时会考虑间隔和交错练习，但不会安排复习，也没有 Anki 或日历整合。用户经常要求这两项功能。另一个相关问题是结束标准。一位用户说，`teach` "很擅长编写下一堂课，却不太擅长判断什么时候应该停止，改为复习或真实练习"。如果你想复习或训练，而不是学习新内容，请主动要求；技能不会自行提出转换方式。

**它只适用于编程吗？**
不是。用户报告的大多数用途都与编程无关：韩语、日语正式语体、钢琴、吉他、棋盘游戏设计、OpenSCAD、电影剧情、Azure 和 CCNA 证照、大学考试，以及为八岁和十岁的儿童编写介绍密室逃脱和火蝾螈的可打印读物。此技能没有任何只适用于编程的内容。学习任务、资源、最近发展区和练习在任何领域都同样适用。在编程领域，用户表示此技能最有价值的用途是熟悉陌生代码库或新团队采用的技术，而不是从零开始学习编程语言。

**我应该使用哪个模型？**
没有统一答案，用户报告的差异很大。用户表示，较高的[推理投入程度](https://www.aihero.dev/ai-coding-dictionary/effort)比中等设置能产出更好的课程。一位用户通过 Copilot CLI 使用 Codex 运行相同技能时，只得到一张三十行的 HTML 卡片；Claude Code 却产出了一整堂课。如果组织允许安装技能，它可以不经修改地在 Claude Cowork 中运行。如果课程内容太少，先更换模型、[运行环境](https://www.aihero.dev/ai-coding-dictionary/harness)或推理投入程度，再考虑重写提示。

## 判断是否有效

- 在空目录中，第一件事是访谈你为什么要学，而不是直接产出课程。
- `RESOURCES.md` 先于课程逐渐充实，而且每一课都推荐一项值得你亲自阅读的一手资料。
- 每项课程主张都有链接支持。没有引用的课程等于技能凭记忆教学。
- 一堂课可以在一次学习中完成，并让你能够做一件以前不会做的事。
- 在该文件夹中开启新会话并说"下一课"时，课程会继续，而不是从头开始。
- `learning-records/` 会增加，而且课程不再重复教授你已经展示过的知识。
- 所有课程看起来像一门完整课程：它们会链接到 `assets/` 中的样式表，而不是各自附带样式表。
- 需要判断力的问题会让你去论坛、子版块或课程征求意见，而不只是得到一个答案。

## 适用范围

`teach` 是一个**可随时使用的独立技能**。它不属于构建流程，也不会与工程流程共享产物；只要你仍在学习，就会在自己的目录中使用它。

它唯一真正接近的技能是 [handoff](https://aihero.dev/skills-handoff)。两者一同解决这个问题："如果有人追问我一件自己不懂的事情，我该怎么办？"不要停止追问来学习。使用 `/handoff` 转到教学工作区，在那里用 `/teach` 学习主题，再回来继续原来的工作。另一个接近的选择是 [research](https://aihero.dev/skills-research)，适用于你想要附有引用的文档，而不是课程和长期记忆的情况。如果不确定哪种技能或流程适合你，[ask-matt](https://aihero.dev/skills-ask-matt) 会从所有选项中为你指引。
