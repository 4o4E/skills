## 功能

`grill-me` 会围绕一个**初步想法**持续访谈你，直到你能够作出决定。开始时不需要完整计划，因为这次[会话](https://www.aihero.dev/ai-coding-dictionary/session)的目的就是产出计划。它分**轮次**提问。每一轮都会问完整个**前沿**，也就是所有前置条件已经确定的问题。因此，它绝不会询问一个取决于尚未听到的答案的问题。

它是**[无状态](https://www.aihero.dev/ai-coding-dictionary/stateless)**的。它不写入文件，也不会留下工作区。唯一的结果是你在脑海中形成的、更清晰的想法。

## 何时使用

输入 `/grill-me` 即可调用；[代理](https://www.aihero.dev/ai-coding-dictionary/agent)不会自行调用它。请在**新对话**中启动，不要在代理已经替你写好计划的对话中启动。

只要你有一个值得认真考虑的想法，就可以立即使用（功能、产品方向、业务决定、一篇文章），最好在你还没弄清楚具体内容之前就开始。模糊并不是等待的理由，因为这次会话就是为了消除模糊。如果你已经能够精确说明这件事，就不需要继续追问。

你应根据眼前的情况，从三种追问技能中选择：

- **任何事情，任何地方。** 使用 `grill-me`。它不需要代码仓库，也不写文件；主题也不必与代码有关。
- **需要参照代码库。** 使用 [grill-with-docs](https://aihero.dev/skills-grill-with-docs)。它采用相同的访谈方式，但有[状态](https://www.aihero.dev/ai-coding-dictionary/stateful)：会读取代码，并将学到的内容记录在 `GLOSSARY.md` 和 ADR 中。
- **单次会话无法处理的事情。** 使用 [wayfinder](https://aihero.dev/skills-wayfinder)。它会将工作绘成地图，并在其中安排追问会话。

关闭[计划模式](https://www.aihero.dev/ai-coding-dictionary/agent-mode)。计划模式会促使代理赶快产出计划，而你希望它继续提问。

## 这是一次对话，不是面试

技能提出问题，但**范围由你决定**。很多人会忽略这一点。它决定了一次会话是把想法转成决定，还是产出看似自信的胡言乱语。

失效模式是**被动回答**：面对四十个问题，你都回答“同意，同意，同意”，最后拿到一份代理写好而你只点头的计划。因为过程很长，感觉好像很有成果，但你什么都没决定，结果却看起来比实际情况确定。

主动参与就是引导访谈。如果问题不够详细，就要求进一步说明。如果范围正在偏移，就指出来。回答“我不知道”时，要确实表示不知道。此技能能帮助工程师，但不能取代工程师。结果的质量取决于你回答的质量，而不是问题的数量。

相反的错误也确实存在，但比较少见：访谈持续太久，以至于从未进入写代码阶段。

## 能通过追问解决的事与无法通过追问解决的事

有些问题可以靠讨论回答；有些不行，追问再多也无法让你得到答案。

“要一个长表单还是三个页面？”以及“这个互动给人的感觉应该如何？”都**无法只靠追问回答**。你需要先有东西可以回应，才能回答这类问题。遇到这种情况时，请停止追问。使用 [prototype](https://aihero.dev/skills-prototype) 构建一次性版本，查看之后，再用一句话回来回答。

试图通过讨论解决无法只靠追问回答的问题，会让会话变得太长。代理不断换种说法提问，你不断猜测，范围也会随着不确定性而扩大。

## 判断是否有效

- 你不同意了某些内容。如果你从未提出异议，这次会话就没有必要进行。
- 问题分成几轮提出，而不是长时间一次只问一个；后续轮次也会清楚地依据你先前所说的内容继续提问。
- 你最后得到的结果出乎意料，因为某个问题让你看见一个自己一直在作、却没注意到的决定。
- 结束时，你能够向一个不在场的人说明每项选择的理由。

## 常见问题

**我应该预期有多少问题，怎样知道什么时候结束？**
数轮次，而不是数问题。四轮问了四十六个问题是很普通的会话。当所有前沿问题都已处理，且没有未说明的假设时，会话就结束。

**它问了我两百个问题。出了什么问题？**
通常是范围太大。先请代理把工作拆成较小部分，再逐项追问。会话非常长时也可能偏入**[迟钝区](https://www.aihero.dev/ai-coding-dictionary/smart-zone)**，也就是[上下文窗口](https://www.aihero.dev/ai-coding-dictionary/context-window)已经足够满，导致问题质量变差。

**我可以改回一次问一个问题吗？**
可以。把以下内容加入全局 `CLAUDE.md`：

```
When grilling, ask one question at a time.
```

**如果我确实不知道答案呢？**
直接说明。“我不知道”是有效回答。如果问题无法回答，通常说明应该先制作原型，而不是猜测。

**写规格说明之前，我要先开启新会话吗？**
不需要。这次会话的价值在于你刚刚建立的[上下文](https://www.aihero.dev/ai-coding-dictionary/context)。直接把同一段对话交给 [to-spec](https://aihero.dev/skills-to-spec) 即可。

**模型会有影响吗？**
比多数技能更有影响。追问依赖[模型](https://www.aihero.dev/ai-coding-dictionary/model)本身对系统如何出错的了解，因此请使用能力最强的模型。实施主要依据上下文，所以使用成本较低的模型也可以。

## 适用范围

`grill-me` 是一个**可在任何地方、用于任何主题的独立技能**。由于它无状态，因此可以随处使用。它不需要代码仓库、工作区或设置，也不假定想法与软件有关。人们会用它考虑业务决定、写作和下一步行动：任何自己无法清楚思考的事情。

它与 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 唯一的差别是可移植性。后者也进行相同访谈，但会读取代码库作为参照，并将学到的内容记录在 `GLOSSARY.md` 和 ADR 中。两者底层都使用 [grilling](https://aihero.dev/skills-grilling) 技能。`grill-me` 是由用户调用且不保留状态的入口。

如果追问的内容最后确实变成软件工作，你可以把同一段对话交给 [to-spec](https://aihero.dev/skills-to-spec)，继续进入构建流程（这是一个选项，不是此技能的目的）。如果不确定应使用哪种流程，[ask-matt](https://aihero.dev/skills-ask-matt) 会为你指引。
