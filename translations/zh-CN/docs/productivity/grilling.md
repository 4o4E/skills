## 功能

`grilling` 是一套访谈流程，用于在任何人采取行动之前，严格检验计划、决定或想法。它会把主题绘成一棵**设计树**：每个决定都会分出依赖它的决定，并沿着各个分支逐一访谈，直到没有任何假设尚未说明。

它不会一次只问一个问题，也不会一次问所有问题。每一**轮**都会询问整个**前沿**：所有前置条件已确定的决定，仅此而已。如果两个问题中有一个依赖另一个，它们就不会出现在同一轮；取决于尚未确定答案的问题，应放在后续轮次。你的回答确定了决定，前沿向外推进，下一轮就会询问这些决定解除的问题。通常十三个问题会分成大约三轮，而不是十三轮。

## 何时使用

输入 `/grilling`，或者在任务符合条件时，[代理](https://www.aihero.dev/ai-coding-dictionary/agent)会自行调用。它是追问类[技能](https://www.aihero.dev/ai-coding-dictionary/skill)中唯一由模型调用的技能，因此你很少需要直接输入。通常由你已经输入的其他技能替你运行它。

直接输入 `/grilling` 会启动普通访谈，不做其他事情。如果你需要更多功能：

| 你的情况 | 使用方式 |
| --- | --- |
| 你不在工作目录中 | [grill-me](https://aihero.dev/skills-grill-me)：相同的[会话](https://www.aihero.dev/ai-coding-dictionary/session)，名称可由你调用，代理不会自行调用 |
| 你在工作目录中 | [grill-with-docs](https://aihero.dev/skills-grill-with-docs)：进行相同的会话，并在过程中写入 `GLOSSARY.md` 和 ADR |
| 工作量大到无法在一次会话中处理 | [wayfinder](https://aihero.dev/skills-wayfinder)：绘制地图，并在决策工单中进行追问 |
| 无法通过讨论决定的问题：某件事看起来或感觉上应当如何 | [prototype](https://aihero.dev/skills-prototype)：先构建一次性版本，再回来继续 |
| 你自己编写的技能需要访谈流程 | 在该技能中调用 `/grilling`，不要另写一套访谈流程 |

## 轮次、前沿，以及谁来作决定

此技能建立在三个概念上。

**设计树**是主题的模型：其中包含相互依赖的决定。**前沿**是一组前置条件都已确定的决定：代理目前唯一可以询问的问题。**轮次**就是一次完整提出、完整回答的前沿。

每一轮中的问题都采用固定格式：在 `❓` 后写编号和标题，然后写问题内容，接着在单独的 `➡️` 行上写代理推荐的答案。这样你就能用编号回答整轮问题（“1，是；2，第二个选项；3，不是，原因如下”），不用引用问题原文。这个格式有一个已知问题：推荐答案有时会反对问题本身的措辞，因此同意推荐答案就等于对问题回答“否”。遇到这种情况，请直接回答推荐内容，并说明这一点。

设计的另一半是区分事实与决定。查明事实是此技能的职责。如果某个前沿问题需要[环境](https://www.aihero.dev/ai-coding-dictionary/environment)信息才能确定，代理会派遣[子代理](https://www.aihero.dev/ai-coding-dictionary/subagent)去查明，而不是询问你。这一轮不会等待调查；只有依赖调查结果的问题需要等待。决定由你作出，代理必须等待。如果运行 `grilling` 的代理自行替你作出决定，就违反了此技能的要求。当前沿为空时，会话结束。此时代理会等待你确认双方已有共同理解，然后才根据你们同意的内容采取行动。

前沿有一个限制。代理凭判断选择前沿，不会根据图表计算。因此，它可能在同一轮中提出两个问题，之后才发现一个答案本来应该改变另一个问题。唯一的保护方法是告诉代理。这样受影响的分支会在下一轮重新打开。

## 常见问题

**我可以改回一次只问一个问题吗？**
可以，而且不少用户都这样做。把以下内容加入全局 `CLAUDE.md`：

```
When grilling, ask one question at a time.
```

并非所有人都喜欢默认的分轮提问方式。阅读速度较慢、使用第二语言工作，或借助逐个提问来集中注意力的用户表示，一次一个问题更适合他们。这是受支持的设置，不是临时绕过方法。

**`/batch-grill-me` 去哪里了？**
它并入了此技能。分轮提问曾短暂作为单独技能发布，之后移入 `grilling` 本身，因此所有基于此基础技能构建的功能（`grill-me`、`grill-with-docs`、`triage`、`wayfinder`）都同时获得了这项功能。不需要安装 `batch-grill-me`，也没有单独的逐个提问技能；要恢复一次只问一个问题，请使用上面的 `CLAUDE.md` 设置。

**一次问完一整轮，肯定会遗漏我先前回答本来会引出的问题。不是吗？**
这是用户对分轮提问最常见的质疑，前沿的设计就是答案。一轮只包含彼此不依赖的问题，因此一轮中的任何答案都不会使同一轮的另一个问题失效。你的回答仍会改变之后的内容，因为代理会从头计算每一轮。确实会有一些差别，但比“一次问完所有问题”这个说法暗示的情况要少。请参阅上面关于前沿的限制。

**它问完问题就开始构建了。**
确认关卡就是为此而设。只有你说双方已经达成共同理解时，此技能才算完成，前沿为空并不代表完成。较弱、较快的[模型](https://www.aihero.dev/ai-coding-dictionary/model)仍可能跳过此关卡。用户报告说，这种情况最常发生在较低投入设置或非前沿模型上，它们会把“持续访谈，直到双方达成共同理解”简化为几个问题和一份提纲。如果你的模型也这样做，可靠的解决办法是在自己的 `AGENTS.md` 或 `CLAUDE.md` 中加一行，告诉代理未经许可不得实施。

**它没有询问我，而是自行回答了问题。**
这是运行中的缺陷，也是技能文本要区分事实和决定的原因。这种情况最常发生在其他技能为了处理工单而运行 `grilling`，代理却把该任务当成可以继续自行决定的许可。同样的限制也解释了为什么没有异步模式。有人要求设计一种变体，让它读取 GitHub 议题并发布一份汇总决定的备忘录；那会是另一种技能，因为没有人回答的追问会产生代理的意见，而不是你的决定。

**我可以限制问题数量吗？**
不可以，这是有意排除的功能。有些计划需要三个问题，有些需要五十个；固定上限要么会截断复杂情况，要么让简单情况显得限制武断。预期的控制方式是用自然语言告诉它收尾，或停止并接受当前计划。如果会话持续很久，通常是因为范围太大；请拆分工作，再分别追问。

**我单独安装了 `grill-me`，但什么都没发生。**
`grill-me` 只有一行，整个正文就是“运行一个 `/grilling` 会话”，因此也需要安装此技能。`grill-with-docs` 也是如此，此外它还需要 [domain-modeling](https://aihero.dev/skills-domain-modeling)。安装整套技能可以避免这个问题；如果选择性安装，也要一并安装基础技能。

**`grill-with-docs` 已运行，但它从未加载 `grilling`。**
这是一个真实存在且尚未修复的缺陷，用户在不同[运行环境](https://www.aihero.dev/ai-coding-dictionary/harness)和模型中都遇到过。一个技能提到另一个技能，并不能可靠地让另一个技能加载；而 `grill-with-docs` 提到了两个技能。其迹象是会话一次问完所有内容，且没有推荐答案。这表示模型在临时编写访谈，而不是运行此技能。直接询问代理是否加载了 `grilling` 和 `domain-modeling`，通常可以恢复运行。

## 判断是否有效

- 每一轮的问题都以编号列表出现，每个问题的推荐答案都在单独的 `➡️` 行上；你可以只用编号回答整轮。
- 同一轮中没有问题需要先回答另一个问题。
- 后续轮次会询问第一轮无法提出的问题。
- 代理会自行查找事实（读取文件、派遣子代理），而不是询问它本来可以查明的内容。
- 后台研究不会使当前轮停滞，只有依赖研究结果的问题需要等待。
- 代理会在结束时停下并请你确认双方已有共同理解，而不是直接开始工作。
- 问题数量多，轮次数量少。

## 适用范围

`grilling` 是一项**基础技能**，而不是预先安排的工作步骤：它将访谈技巧作为唯一可信来源集中在一处，让每项需要访谈的技能都来使用它，而不是自行编写访谈。[grill-me](https://aihero.dev/skills-grill-me) 和 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 是由用户调用的两个入口；而 `grill-with-docs` 会在 [to-spec](https://aihero.dev/skills-to-spec) 之前启动主要构建流程。[wayfinder](https://aihero.dev/skills-wayfinder) 使用它来解决决策工单，[triage](https://aihero.dev/skills-triage) 使用它来将模糊报告追问成可处理的问题，[improve-codebase-architecture](https://aihero.dev/skills-improve-codebase-architecture) 则在你选定适合加深模块的候选项后，使用它沿着设计树逐项询问。如果不确定应该从哪个入口开始，[ask-matt](https://aihero.dev/skills-ask-matt) 会为你指引。
