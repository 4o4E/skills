# 阶段边界

**阶段**是一次会话中的一段工作：深入追问、实现、质量保证。这个定义有意保持模糊：当你觉得"好了，这部分做完了"，阶段就结束。

**阶段边界**是两个阶段之间的间隔，也是唯一应该作出以下选择的地方。阶段进行中没有什么需要决定：继续，或把剩余工作拆分给子代理。阶段进行到一半时压缩上下文，会让代理失去思路。

## 五种选择

| 选择 | 作用 |
| ------------ | --------------------------------------------------------------- |
| **Continue** | 留在当前会话中，不进行任何上下文切换。 |
| **`/clear`** | 清空上下文窗口，从头开始。 |
| **`/handoff`** | 编写可移植的 Markdown 文件，并在任意位置以此开始一个会话。 |
| **Subagent** | 将任务交给自己的上下文窗口，并取得报告。 |
| **`/compact`** | 压缩当前上下文，并用摘要开始一个新会话。 |

## 判断路径

在阶段边界处从上往下判断。遇到的第一个**是**就是答案。

**1. 能否在当前会话中继续？**有两种情况可以：下一阶段需要把本阶段当作**一手资料**，或者你还有足够的[智能区(smart zone)](https://www.aihero.dev/ai-coding-dictionary/smart-zone)可供下一阶段使用(约 150k tokens)。深入追问 → 实现是典型情况：实现需要逐字参考推理过程，而不是摘要。继续既不耗费资源，也不会丢失内容，因此在考虑其他选项前应先判断是否可继续。

**2. 当前上下文与接下来的工作无关吗？**当前会话中的所有内容(探索、决定、行不通的尝试)是否都可以丢弃？如果是，使用 **`/clear`**。这是最便宜的做法：不耗时，并会归还整个窗口。`/clear` 也不会终止会话：旧会话之后仍可恢复。

如果判断错误，代价无法挽回。清除**相关**上下文会丢失你构建内容背后的**原因**，之后无论把差异读多少遍都无法找回。

**3. 是否需要移交？**只有在以下情况才需要使用 `/handoff`：

- 切换到**新运行环境**(Claude → Codex)，
- 转到**新目录**或仓库，
- 将工作交给**同事**，
- 或在阶段中途发现并拆分一个旁支任务，且不希望打断当前工作。

这些就是全部情况。`/handoff` 提供的是**可移植性**：可以带走的文件。如果没有内容需要带走，就不需要它。

**4. 任务能否在无人值守时完成？**范围是否足够明确，能够在你离开键盘时继续执行，不需要任何引导？如果可以，就交给子代理，并保持当前会话不变。自动化审查是典型例子：代理读取差异并汇报，而你无需参与。

**5. 其他情况下使用 `/compact`。**上下文仍然相关、使用相同运行环境和目录，而且你需要继续参与：这就是判断路径的终点，并且很常见。传入指示(`/compact 我们接下来要对这个区域做质量保证`)，让摘要保留下一阶段所需的信息。

`/compact` 是**默认选择，但不是优先选择**。它位于路径末尾，因为前四个问题都能找到成本更低或更精确的做法。若一开始就盲目选择该项，失误模式在于新会话容易将压缩简化后的结论当成绝对事实，进而做出错误判断。

## 一手资料与二手资料

除 **Continue** 之外，其他每种选择都会把**一手资料**变为**二手资料**：会话的实际过程会被摘要取代。交换结果始终相同：

| 来源 | 信息 | 噪声 | 可用空间 |
| --------------------------------- | ----------- | ----- | ------------ |
| 一手资料(Continue) | 完整 | 很多 | 很少 |
| 二手资料(`/compact`、`/handoff`) | 有损 | 较少 | 很多 |

因此问题 1 必须放在第一位。只有留在原处的成本高于节省的成本时，才值得接受信息损失。

## 这些选择需要判断

这些问题并没有客观答案：它们带有个人判断，同一个阶段边界在不同日期可能会有不同选择。关键是在边界处依序提出这些问题，而不是在工作进行到一半时才问。
