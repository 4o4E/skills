# 向导

**向导**是一种 Bash 脚本，用于逐步引导用户完成手动操作。这些操作手动完成很繁琐，而且每次都要向 AI 重新解释也很麻烦。脚本会打开每个网址，准确说明要点击和复制的内容，收集输入的值，将值写入应保存的位置(`.env`、GitHub 密钥)，在每个阶段进行确认，并显示剩余阶段数量。它可以配置第三方服务、运行一次性迁移，或将项目从一种状态转变为另一种状态。

所需的交互体验已由 [template.sh](template.sh) 提供：逐阶段显示进度、要求确认、跨平台打开网址(包括 WSL)、隐藏密钥输入、幂等地更新 `.env`、写入 `gh secret`/`gh variable`，以及结束摘要。**你的工作仅限于界定流程并编写各个阶段。**`STAGES` 标记上方的函数库在每个向导中都相同；保持一致正是其目的：切勿手动编辑该部分。

向导默认只使用一次：为单次运行而编写，保存到临时目录或 `scripts/` 路径，并在工作完成后删除。只有当用户希望在仓库中保留可重复使用的设置流程时，才提交向导。

## 流程

### 1. 界定流程

找出用户必须手动执行的每个步骤，以及过程中需要收集的每个值。先阅读仓库，不要贸然提问：

- 对于设置流程：检查 `.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置和 `.github/workflows/*`(每个 `secrets.*`/`vars.*` 引用都代表向导必须生成的一个值)。
- 对于迁移或切换：检查当前状态、目标状态，以及两者之间不可逆的操作。

然后按顺序向用户展示各个阶段及每个阶段产生的值，并请用户确认：他们可以增加、删除或重新排序。

**完成条件：**每个阶段都有明确名称和顺序；对于每个收集的值，你都知道：(a) 用户从哪里获取；(b) 将它写到哪里(`.env`、GitHub 密钥、两者都写或不写；某些阶段只是执行操作)；(c) 它是否属于密钥(输入时隐藏)或公开值。

### 2. 规划每个阶段的操作路径

对于每个阶段，写出用户遵循的准确路径：要打开哪个网址、要在那里执行什么操作、在哪里可以看到某个值，以及该值要填写哪个变量。例如："控制台 → 开发者 → API 密钥 → 显示测试密钥 → 复制"。如果你不知道当前用户界面或准确命令，请说明这一点并询问用户或检查文档：切勿编造可能不存在的步骤。

**完成条件：**每个阶段都有陌生用户也能遵循的具体说明。

### 3. 编写向导

将 `template.sh` 复制到目标路径。将示例阶段替换为按依赖顺序排列的阶段，每个步骤对应一个 `stage`。使用函数库提供的帮助函数：`stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm`。将 `TOTAL_STAGES` 设为你编写的阶段数量。

遵循模板设定的标准：在询问值之前先打开网址；所有密钥都使用 `ask_secret`；每个需要保存的值都使用 `write_env`；只对 CI 实际需要的值使用 `set_secret`；任何不可逆操作之前都要使用 `confirm`。每个 `stage` 都会清空屏幕，因此只显示当前步骤；每个阶段只处理一项明确任务，以免用户需要查看的内容滚出屏幕。不要修改标记上方的函数库。

### 4. 验证并交接

- 运行 `bash -n <script>`；如果 `shellcheck` 可用，则运行 `shellcheck`。
- 运行 `chmod +x <script>`。
- 不要自行端到端运行脚本：它会打开浏览器并等待用户输入。改为静态追踪脚本：确认第 1 步中的每个值都已收集，并写入第 1 步指定的位置；确认每个 `set_secret` 名称都与 CI 中的 `secrets.*` 引用完全匹配。
- 告知用户如何运行脚本。如果这是可重复的设置流程，则提交脚本并在 README 中添加链接，让下一位用户可以直接运行脚本，而不必询问 AI。
