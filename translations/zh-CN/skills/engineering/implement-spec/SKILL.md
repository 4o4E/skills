已向你提供一份规格说明。此规格说明应该关联了说明如何实现该规格说明的工单。

应该已经向你提供了议题跟踪系统。如果没有，请告知用户运行 `/setup-matt-pocock-skills`。

目标是在一个**集成分支**上完整实现整个规格说明，并按照议题跟踪系统关闭工作的方式解决每个工单。

工单不是步骤列表，而是一个**带依赖关系的任务图**。这意味着任何时候都有一组可以领取的前沿工单。

与子代理的沟通应当简洁。主要通过**上下文指针**沟通：指向规格说明、工单、研究笔记和先前提交。不要重复指针所指内容中已经存在的信息。

尽可能在后台运行**实施子代理**，以最大限度提高并发能力。

## 步骤

1. 阅读规格说明和工单，了解任务图。

2. （可选）使用**探索子代理**执行工单所需的探索工作，例如查找相关代码库文件或外部文档。确保探索子代理可以保存文件；它应将 Markdown 笔记保存到仓库外、所有未来子代理都能访问的目录。这样**实施子代理**就能专注于实现工作，而不必探索。

3. 创建集成分支。如果议题跟踪系统通过 PR 关闭工作，或用户要求创建 PR，则在步骤 5 中第一次合并后打开草稿 PR（分支领先 `main` 的提交数为零时，无法打开 PR），并标记为关闭此规格说明及其工单。

4. 使用**实施子代理**实现每个工单，每个子代理都在自己的分支和独立 worktree 中工作。每个实施子代理都要：
   - 在开始前确认其 worktree 基于集成分支；如果不是，则重置到该分支。
   - 调用 Skill 工具并使用 `tdd` 构建工单要求的内容。
   - 在报告完成前，将集成分支的最新内容合并到自己的分支。

5. **实施子代理**完成后，使用**合并子代理**将其工作合并到集成分支。

6. 一旦有新的工单解除阻塞进入就绪状态，立即启动更多**实施子代理**并发处理，以实现最大并发度。

7. 完成所有工单后，在集成分支上调用 Skill 工具并使用 `code-review`。由一个**实施子代理**一次性修复代码审查提出的所有问题。

8. 如果存在草稿 PR，将其标记为准备审查。否则，按照议题跟踪系统关闭工单的方式逐一解决，并报告集成分支。

9. 清理所有**实施子代理**的 worktree。
