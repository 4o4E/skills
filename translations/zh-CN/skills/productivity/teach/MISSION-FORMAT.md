# MISSION.md 格式

`MISSION.md` 保存在工作区根目录，记录用户学习此主题的_原因_。每项教学决定（下一步教什么、展示哪些资源、设计哪些练习）都应以此文件为依据。

## 模板

```md
# 学习任务：{主题}

## 原因
{用一到三句话说明用户要实现的具体现实目标。掌握这项技能后，用户的生活或工作会发生什么变化？避免使用“理解 X”之类抽象说法，应继续追问其背后的实际成果。}

## 成功的表现
- {用户将能够做的一项具体、可观察的事情}
- {另一项具体事情}
- {……}

## 限制条件
- {时间、预算、已有承诺、学习偏好，以及任何会限制教学方式的因素}

## 不涉及的内容
- {用户明确表示现在不想深入的相邻主题，用以保护最近发展区}
```

## 规则

- **每个工作区只有一项学习任务。** 如果用户想学习两个互不相关的主题，就建立两个工作区。
- **采用具体表达，不用抽象说法。** “十月前跑完半程马拉松”比“身体更健康”好。“为团队发布一个 Rust 命令行工具”比“学习 Rust”好。
- **对模糊表述提出质疑。** 如果用户说不清原因，就在写入任何内容之前询问他们。糟糕的学习任务比没有学习任务更糟。
- **现实改变时修订。** 用户的目标发生变化时，应更新此文件；不要让过时的任务继续引导未来的会话。
- **保持简短。** 如果 `MISSION.md` 超出一个屏幕长度，它就不再是方向指引，而成了计划。
