# 学习记录格式

学习记录保存在 `./learning-records/`，使用连续编号：`0001-slug.md`、`0002-slug.md` 等。只有在第一次需要写入记录时才创建此目录。

学习记录相当于教学领域的 ADR：用来记录非显而易见的经验、关键见解和用户陈述的已有知识，以引导未来的教学。应根据这些记录计算最近发展区。

## 模板

```md
# {本次学会或确认内容的简短标题}

{用一到三句话说明学到了什么(或确认了哪些已有知识)，以及这对之后的学习为什么重要。}
```

这就是全部格式。学习记录可以只有一个段落。记录的价值在于说明用户现在已经知道什么，以及这会如何改变之后的教学内容；价值不在于填写各个章节。

## 可选部分

只有在确实能带来价值时才加入这些部分。大多数记录不需要它们。

- **Status** frontmatter(`active | superseded by LR-NNNN`)：如果更早的理解后来被证明有误，并已由新理解取代，此字段很有用。
- **Evidence**：用户如何展现出对内容的理解(回答了问题、完成了练习、提及了以往经验)。如果之后可能需要重新检查这一主张，此字段很有用。
- **Implications**：这能开启什么，或排除什么。如果其中的影响不明显，记录下来会有价值。

## 编号

检查 `./learning-records/` 中的最高编号，并将其加一。

## 何时写入学习记录

出现以下任一情况时，就写入一条记录：

1. **用户展现出对非简单内容的真实理解**：不只是听说过，而是有证据表明他们能够正确运用概念。这为未来的教学设定了新的起点。
2. **用户透露自己已有相关知识**："X 我已经会了。"请记录下来，避免之后重复教学。也应记录用户声称的掌握程度。
3. **用户纠正了一个错误认识**：用户原本持有错误想法，现在明白其缘由。这很有价值，因为它可以预示用户在相关内容上可能遇到的困难。
4. **学习任务因学习而改变**：用户发现自己关心的事情与原先想象的不同。请链接到 [[MISSION.md]] 并更新该文件。

### 哪些情况不符合记录条件

- 只是讲过某项内容。讲过不等于学会。等到有证据再记录。
- 已经简洁地记录在 [[GLOSSARY.md]] 中的术语定义。不要重复。
- 按会话记录活动。学习记录不是日志，而是值得指导未来教学的见解。

## 取代旧记录

后来的记录与较早的记录相矛盾时(用户加深了理解，或纠正了理解)，应将旧记录标记为 `Status: superseded by LR-NNNN`，而不是删除。理解如何演变这一过程本身就是有用的信息。
